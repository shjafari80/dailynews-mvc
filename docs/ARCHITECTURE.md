# Architecture & Folder Structure

This is a standard ASP.NET Core MVC layout, with an `Admin` Area for the
management panel. Nothing exotic — chosen deliberately so the structure
stays easy to follow phase by phase.

## Why this structure

- **`Areas/Admin`** keeps every admin-only file physically separate from
  the public site. Nothing in `Controllers/` or the root `Views/` needs to
  know the admin panel exists.
- **`Models/NewsDbContext.cs`** is the single source of truth for seed
  data during Phases 1–3. Once Phase 4 adds real admin CRUD and API sync,
  this seed data becomes just the initial bootstrap, not the only way data
  gets in.
- **`Migrations/`** is auto-generated by EF Core (`dotnet ef migrations
  add <Name>`) — nothing here should be hand-written from scratch, though
  early on (before any real deployment) it's fine to hand-edit seed values
  directly in a migration if needed.
- **No `Services/` folder yet** — deliberately, since Phases 1–3 don't need
  one. Phase 4 will likely introduce something like:
  ```
  Services/
    INewsApiService.cs
    NewsApiService.cs
  ```
  once real API calls need a home outside the controllers.

## Data model (Phase 2 target)

```
Category (1) ───< (many) News (many) >─── (1) Author
```

- `Category`: `Id`, `Name`
- `Author`: `Id`, `Name`, `Bio`, `ImageUrl`
- `News`: `Id`, `Title`, `Content`, `PublishDate`, `ImageUrl`,
  `CategoryId` (FK), `AuthorId` (FK)

This stays intentionally simple through Phase 3. Phase 4 may extend `News`
with an optional `SourceUrl` / `SourceName` field once external API
articles start flowing in, so real articles can link back to their
original source.

## Request flow (public site)

```
Browser → HomeController.Index() → NewsDbContext (via EF Core)
        → Views/Home/Index.cshtml → rendered HTML
```

## Request flow (admin panel)

```
Browser → /Admin/News → Areas/Admin/Controllers/NewsController
        → NewsDbContext → Areas/Admin/Views/News/*.cshtml
```

Both controllers share the same `NewsDbContext` — there is only one
database, the Admin Area just exposes write operations that the public
site doesn't.
